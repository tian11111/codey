# 提示词优化功能实现方案

## 目标
用户配置一个 OpenAI 兼容的 Chat Completions API（独立于当前线路），在 Codex 输入框旁注入「优化」按钮；输入内容后点击按钮，后端调用 API 优化提示词，成功后直接替换输入框内容。凭据走脱敏存储，前端不接触明文 API Key。

## 架构决策
- **API 调用放后端（Rust）**：渲染层从不直连外部 API（仓库无先例，额度/模型都走 bridge）。新增命令 `/api/optimize_prompt`，复用 `state.http_client` 与 vendor `test_relay_profile` 的 Chat Completions 请求模式（含 404 自动补 `/v1` 重试）。
- **独立配置**：`CodeyConfig` 新增 `promptOptimization` 结构，仿 `NotificationChannelConfig` 凭据模式（`apiKeyConfigured` / `clearApiKey` / `merge_redacted_secrets`），`redacted_config` 清空 key。
- **不要求重启**：注入脚本运行期通过 `/settings/get` 读 `enabled`，并监听 overlay 保存后派发的 `codey:config-changed` 事件重新拉取，开关即时生效。
- **请求参数**：`chat/completions`，`messages = [system(优化指令), user(原文)]`，`max_tokens=2048`，单请求超时 60s（前端 `withTimeout` 75s），输入文本上限 32K 字符。优化指令可自定义，留空用内置默认（直接输出优化结果、不加解释/代码围栏）。
- **错误纪律**：错误信息脱敏（不含 API Key），日志只记错误类别与线路/模型信息，不记提示词正文（沿用项目日志规范）。

## 改动文件

### 后端（Rust）
1. **`backend/src/config.rs`**：新增 `PromptOptimizationConfig`（`enabled`、`baseUrl`、`apiKey`、`apiKeyConfigured`、`clearApiKey`(skip_serializing)、`model`、`instruction`）+ `merge_redacted_secrets(&previous)` + `is_configured()`；`CodeyConfig` 加 `prompt_optimization` 字段（default + normalize）。
2. **新建 `backend/src/prompt_optimization.rs`**：核心逻辑 `optimize_prompt(config, text)` —— 校验配置（baseUrl 必须 http/https、model/key 非空）、拼端点（去尾斜杠、404 补 `/v1`）、请求、解析 `choices[0].message.content`（兼容字符串与分段数组）、错误脱敏；含单元测试。
3. **新建 `backend/src/commands/prompt_optimization.rs`**：`optimize_prompt`（参数 `text`）、`test_prompt_optimization`（最小请求验证连通性）两个 handler；`commands.rs` 内声明子模块。
4. **`backend/src/commands.rs`**：`invoke_api` match 加两个命令分支；`redacted_config` 清空 `promptOptimization.apiKey` 并置 `apiKeyConfigured`；`save_codey_config_locked` 中 `merge_redacted_secrets` + 白名单拷贝新字段。
5. **`backend/src/cdp.rs`**：`include_str!` 嵌入新注入脚本 + `builtin_scripts` 数组登记（id `prompt-optimize`、名称、探针表达式，暴露 `window.__codeyPromptOptimize.snapshot()` 供注入健康检查展示）。

### 渲染层注入脚本
6. **新建 `public/prompt-optimize.js`**（`build-overlay.mjs` 自动 glob，无需改构建脚本）：
   - 挂载检测：主锚点 `[data-above-composer-conversation-id]`（已知位于 composer 上方）向下找 composer 容器内 `textarea`；兜底扫描主内容区可见 `textarea` / `[contenteditable=true]`；找不到则隐藏按钮。
   - 按钮：小图标「优化」按钮，`data-codey-prompt-optimize` 标记 + 自带 `<style>` 规则 + `-webkit-app-region: no-drag`，捕获阶段事件监听（沿用 renderer-inject.js 模式）；点击 → `__codexSessionDeleteBridge("/api/optimize_prompt", {text})` → 成功用原生 value setter + `input` 事件派发替换内容（兼容 React 受控组件），失败保留原文并显示简短错误；请求期间按钮置忙禁用。
   - 观察器：MutationObserver + 去抖重挂载；`codey:config-changed` 事件触发重新拉 `/settings/get`。
7. **`public/codey-inject.js`**：`codeyOwnedSelector` 列表加 `data-codey-prompt-optimize`，避免增量扫描把按钮当新节点循环重扫。

8. **`src/api.ts`**：白名单加 `optimize_prompt`、`test_prompt_optimization`。
9. **`src/App.types.ts`**：`PromptOptimizationConfig` 类型 + `Config` 字段。
10. **新建 `src/PromptOptimizationCard.tsx`**：开关（enabled）、baseUrl、model、API Key（password 输入，placeholder「已保存，输入新值可替换」+「清除已保存的 API Key」按钮，复用 `.notification-secret-action` 样式）、自定义指令 textarea、「测试」按钮 + `InlineResult`（`withTimeout` 12s）。受控组件，走现有 `editConfig` → `save_codey_config` 流程。
11. **`src/App.tsx`**：渲染新卡片（full-row section）；**`src/AppSections.tsx`** 导出；`src/styles.css` 按需少量补充。

### 测试
12. **新建 `tests/prompt-optimize.test.mjs`**：沿用 `node:test` + vm sandbox 模式（仿 settings-button.test.mjs）——按钮在 enabled+找到输入框时挂载、点击调用正确 bridge 路径、成功替换文本并派发 input 事件、失败保留原文、disabled 不挂载、无输入框不挂载、mutation 后重挂载。

## 验证
- `npm run check`（node --check + tsc）、`npm run test:js`、`cargo test --workspace`（或 `--manifest-path Cargo.toml`）、`npm run vite:build`（确认压缩管线对新脚本无回归）。
- 实机验证说明：本环境无法启动真实 Codex，composer 选择器采用多级兜底策略；交付后需在真机上确认按钮挂载位置（如锚点失效，仅需调整 `public/prompt-optimize.js` 的选择器）。

## 风险与缓解
- **Codex composer DOM 未知**（仓库无先例）：多级检测 + 兜底 + 找不到即隐藏，不干扰页面。
- **bridge 串行通道**：60s 优化请求期间其他控制台命令排队 —— 用户本就在等待优化结果，可接受。
- **输出长度**：`max_tokens` 与响应大小上限双重约束，防止上游返回超大正文。
